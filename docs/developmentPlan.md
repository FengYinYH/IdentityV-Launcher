## PLAN-UI：跨平台新 UI

**近期目标：RC4。状态：方向确定，未实现。** 所有者希望在 RC4 直接重构跨平台新 UI，新增窗口设置与 UI 重排一起安排，不在旧界面先堆功能。

- 保留现有下载/校验/修复、两服独立安装与运行管理、可选登录组件、多语言、可理解进度及错误恢复。
- 跨平台 UI 不等于当前 Wine/runtime 或所有游戏后端已支持跨平台。框架、目标平台、每个平台运行/安装支持矩阵尚需确定，不能擅自把“跨平台”扩成所有系统同日完整交付。
- 平台原生功能分别适配，尤其 macOS 系统全屏、Game Mode、刘海安全区与权限。
- 建议实施顺序：定框架/范围和交互 → 隔离 UI 候选接现有后端 → 初始窗口能力 → 登录健康/耗时与回归 → 独立发行验收。该顺序是工程建议，不新增发布承诺。

## PLAN-WINDOW：初始窗口

**近期目标：与 RC4 新 UI 一起实现。状态：需求明确，未实现。**

### 确定设计

1. 提供初始分辨率设置，保持原像素清晰渲染；区分游戏渲染像素、macOS 逻辑点、内容区和外框。
2. 启动后默认居中：处理游戏启动期间自己的尺寸切换，不能仅居中最早出现的小窗；启动期调整有截止条件，不持续抢焦点或强制后续用户拖动。
3. 提供全屏启动选项。macOS 指窗口绿灯式的系统原生全屏/独立 Space，不是游戏内 Windows 独占/准独占“完全全屏”。正确 Game Mode 与刘海避让是验收目标，不能只因进入全屏就断言已满足。
4. **超屏窗口化允许，但确认后放行**：用户选择超过屏幕可用范围的分辨率且不选全屏时，弹窗说明不建议及越屏后果，允许继续或取消；不静默缩小、不强制全屏、不禁止保存。
5. 超屏情形优先保证标题/控制栏和红绿灯可见可操作；可牺牲严格几何居中，允许部分内容越屏。判断须计入目标屏幕可用区域、系统缩放、外框，不仅比较物理分辨率。

### 未决而非已批准

- 预设/自定义编辑方式、默认值、目标显示器选择、确认提示是否记忆及再次触发条件。
- 历史 1080p 是参考，不等于已授权每次静默改写游戏持久设置。“为稳定初版而暂缓自定义”的历史动机没有可靠证据，不补写旧史。
- Windows 等平台的全屏语义和验收另定，不能机械复制 macOS Space 实现。

### 验收矩阵

- 冷/暖启动、游戏热更新后重启：最终大小/位置正确，不重复启动。
- 2x/非2x、多显示器、缩放/刷新率变化、目标显示器拔出：控制栏可操作，比例清晰。
- 窗口化→系统全屏→退出全屏：Game Mode/刘海、恢复尺寸位置分别验证。
- 超屏组合：确认/取消均符合选择；取消无副作用，确认保留可操作控制栏。
- 用户启动期后拖动或改大小：不被后台机制反复夺回；启动失败时校正器能停止。

## PLAN-MACOS14：最低系统目标

2026-11-05 所有者明确最低目标为 macOS 14。第一方 App/helpers 的 deployment target 已为 14，但当前下载 runtime 的 DXMT winemetal.so 实际为 15，完整产品尚不满足。优先在隔离环境准备匹配 Wine ABI 的 LLVM15/mingw 构建输入，重建并审计 DXMT 的 14/Metal3.1 分支；不能只改最低版本号。macOS14 VM 覆盖原生界面/安装/下载/续传/校验与游戏进程，真实14 GPU再验图形/输入/音频，15+验Metal3.2回归；详细证据与矩阵见[DXMT兼容专题](../runtimeManifest/dxmt080MacOS14Compatibility.md#rc5-build-13-接续与-macos-14-测试计划2026-11-05)。当前工具链缺口及14实机仍阻碍完整支持声明。


2026-11-05 成本复核后的边界：所有者只接受小范围14处理，不接受大量适配。已核验官方0.74仍15、0.61虽14但为旧引擎降级；现成LLVM静态库也为15。缺工具的旧判断已由发现归档工具链纠正，但仍无证据证明仅需小打包。停止本轮14推进，保留15+方案，不启动完整重建；技术退路及条件留[兼容专题](../runtimeManifest/dxmt080MacOS14Compatibility.md#成本边界复核与本轮停止2026-11-05)，不作为交付承诺。
