# RC1 默认游戏目录迁移

RC1 将默认游戏数据放在中文目录 `~/Library/Application Support/第五人格`。RC2 使用同级 ASCII 目录 `IdentityV`。首次读取产品状态或执行需要写入的管理操作时，启动器只在记录能证明其管理着该目录中的国服或国际服游戏后，才原子地把旧根目录改名；游戏文件本身不复制。

这样迁移的目的是保持已安装游戏和 Wine prefix 的关联，同时让后续下载、更新和运行路径不再依赖中文目录。目录名可能被用户或其他工具占用，因此只有 `products.json` 或 `installation.json` 中的 `gameRoot` 精确指向旧根下 `CN/game` 或 `Global/game`、卷 UUID 与相对路径均可验证、游戏目录是真实目录且包含 MZ 可执行文件时，才认定为管理器拥有。其他旧目录不动；即使同级 `IdentityV` 已存在，只要旧目录没有管理器所有权，也不会阻止正常使用新目录。

## 迁移内容与拒绝条件

只更新两份明确传入的状态文件中受管游戏根的 `relativePath`，保留卷 UUID、安装版本、所选产品及未知字段。兼容 `ProductState` 当前 Codable 编码的 `installations` 交替键值数组，也接受对象形式。`installation.json` 的 engine id 不等于磁盘目录名：产品 `mainland` 映射到 `CN/game`，`global` 映射到 `Global/game`。

模块只检查关联 prefix 中指向已确认游戏目录的符号链接：对应的 `drive_c/Games/IdentityV` / `IdentityVGlobal`，以及 `dosdevices` 中可证明目标属于游戏目录的链接；独立的 `D:` 或其他无关 Wine 状态不会被改写。任何指回旧根但无法证明归属的链接都会使迁移停止。源根/目标根/support 不能是符号链接，目录必须在同一文件系统，状态路径不能越界。存在有效受管旧安装而目标目录已存在时，迁移拒绝覆盖。

启动器的入口先判断同一用户是否还有任何 `dwrg.exe` 运行；查询失败按运行中处理。游戏运行期间状态轮询延后迁移，正常退出后再重试；需要迁移的写操作会给出错误并要求先退出，不会擅停游戏。模块还会在实际改动前再次调用运行状态检查。

## 事务与恢复

迁移前会在管理器状态目录取得进程退出即释放的 `flock` 锁，并写 owner-only 的准备日志。执行顺序是旧根改名、更新已确认的 prefix 链接、原子更新状态记录、写入完成快照、移除准备日志。目录改名使用 `RENAME_EXCL`，因此 guard 之后若另一个进程创建了目标目录，内核会拒绝改名而不会覆盖目标。启动器已有的管理器互斥锁负责与状态写入、安装和切换串行。

崩溃后下一次空闲调用先验证日志身份、每个记录文件的原始/更新内容、prefix 链接路径及其新旧目标，再决定恢复；不完整或外部已更改的状态会保留日志并停止，不猜测归属或补造缺失链接。处于旧/新根之一存在的准备事务会回滚到 RC1 状态；启动器紧接着再运行一次迁移，使一次重试即可完成目标迁移。若两根同时存在或同时缺失则需要人工检查，自动流程不会覆盖任何一边。提交快照在 `IdentityVOnMac/MigrationBackups/` 下保留小型记录与链接清单，目录权限为 0700、文件为 0600；它不包含游戏数据。内部恢复 API 仅在当前记录、链接和新根仍与提交状态完全一致时允许反向恢复，避免覆盖迁移后的新状态。

锁文件创建前会先只读验证 support 目录，并在取得锁后重新验证，避免对被拒绝的 support 符号链接写入。所有目录与状态文件修改都基于显式 URL；模块不会自行搜索用户目录或枚举、迁移不相关安装。

## 验证与边界

`productManager/selfTest.command` 会把同一合成测试核接入产品管理器自检，并通过真实的 manager wrapper 验证中断恢复后继续迁移。独立入口 `productManager/LegacyDefaultPathMigrationSelfTest.command` 用于单独运行迁移夹具；调用者须先在目标卷创建空夹具目录，并显式提供该卷 UUID。脚本会核对实际挂载卷，临时文件只建在该夹具目录下并在退出时清除，不会触及用户的游戏安装。

合成用例覆盖真实 `Codable` 字段形态、国服/国际服根与 prefix 更新、inode 保持（证明是目录改名而非游戏复制）、未知 JSON 字段保留、幂等、目标冲突、运行中拒绝、无管理器所有权时与既有 ASCII 目录共存、未知链接拒绝、链接/记录阶段故障回滚、pending journal 恢复、journal 路径篡改拒绝、损坏根和 support 符号链接拒绝，以及 owner-only 快照的恢复。该验证证明的是本地文件事务和路径规则；不代表真实用户目录已经迁移，也不测试游戏运行行为。

适用范围限于 RC1 默认目录布局、schemaVersion 1 的两份管理状态记录及已知 `CN` / `Global` 产品目录。卷未挂载、状态缺失或旧目录不归管理器所有时，模块不主动发现游戏；它也不自动处理自定义目录、额外游戏副本或未知 prefix 链接。对无法确认的数据，安全行为是保留原状并报错。
