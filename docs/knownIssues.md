# 已知问题与当前边界

本页记录公开 RC1 后确认、需要后续版本处理的问题。版本与包的身份以[版本约定](../releasePackaging/versioning.md)和包内 `build-provenance.json` 为准；开发中的补丁不代表 RC1 已包含修复。

## 国服启动延迟时误报 IDV-LAUNCH-203

2026-09-25，风吟用本机 `1.0.0-rc.1-test.2` 启动国服时先收到 `IDV-LAUNCH-203`（20 秒内没有检测到游戏进程），随后游戏仍成功启动。只读检查确认报错后游戏进程已出现；源码中的 `waitForManagedGameStart` 固定等待 20 秒，超时只结束产品管理器的等待并返回错误，不会停止已分离运行的 runner，因此启动可在弹窗之后继续完成。20 秒判定随 2026-09-23 的第一方产品管理器基线进入当前工程；这是当前记录中的首次 `IDV-LAUNCH-203`，不表示启动链路刚刚变慢，也不能归因于本轮 emoji 或音频补丁。

本机旧日志曾记一轮 runner 激活耗时约 11.955 秒；本次日志记录的 runner 激活耗时分别约 33.450 秒和 12.256 秒，与“平时十几秒、首次更慢”的反馈吻合。runner 激活计时和产品管理器 20 秒轮询的起点不是同一项显式记录，故不能还原弹窗相对游戏进程出现的精确时间差；但这次 33 秒的启动链路已足以解释 20 秒检查为何会先超时。后续应把“启动仍在进行”与“启动失败”区分开，延长并明确确认窗口，或持续显示等待状态；超时后不得自动重发启动请求，以免重复启动游戏。原始日志留在本机，不写入公开工程记录。

## 组合 emoji 显示方框

2026-09-23 公开 RC1 的游戏聊天中，部分组合 emoji 显示为方框；截图显示单个基础符号有些可见，后续组合项失效。RC1 的默认 Wine runtime 是 `wine11-codeweavers-26.1-dxmt-0.80-macos15-alpha1-r1`，没有选用仓库中的 emoji2 GDI 候选。原有 emoji2 加本机测试字体的隔离回归通过，但该字体含系统 Arial Unicode 字形，不能直接放入公开发行包。

2026-09-24，改用 OFL 来源的 Noto Sans CJK SC 与 Noto Emoji 构造可分发的单色字体候选，并在隔离 Wine prefix 上通过 `compositeRegression` 的 31 组基础、组合和边界用例；其中 U+200B 必须作为空的零宽字形显式保留，否则未合并 ZWJ 的 GDI 宽度会比 Uniscribe 多一个空格。这个结果只覆盖隔离字体与 GDI 路径；仍须验证游戏内聊天、安装后的新 runtime 切换和公开材料对应关系。复现入口见[emoji 修复](../wineEmojiPatch/README.md)。

同日先安装 `1.0.0-rc.1-test.1` 验证 emoji。随后将录音重采样候选与 emoji2 合成新的不可变 `r1-emoji2-audio1` runtime，测试构建升为 `1.0.0-rc.1-test.2`；该 runtime 从已安装 r1 克隆后只替换 GDI 与 CoreAudio 模块，避免再次下载基础 runtime。公开 RC1 的 Git tag、包和默认 runtime 始终不变。

2026-09-25，风吟在 `test.2` 游戏内聊天复测 A–N 三段 emoji 测试串；新截图中各项均显示为图形，没有看到缺字方框或组合 emoji 被拆开，风吟反馈“好像正常了”。这是该测试构建上的一次正向实机验证，说明候选修复目前看有效；仍需在后续版本复核，不能据此认为公开 RC1 已修复。语音条回听效果另见下节，仍有气泡音。

## 语音消息回听定期破音

2026-09-23，使用 Mac 内置麦克风录制第五人格内的语音消息后，自己点开语音条回听时听到气泡状异音；其他应用没有同类现象。最初将间隔粗估为约三秒。9 月 25 日风吟进一步描述为低于语音响度的背景气泡破裂音，语音连续、没有被切断；听感位置约在 1–2 秒、6–7 秒和 11–12 秒，中心间隔约五秒，故以这次更具体的定位修正最初估计。根因仍未定位到 Wine 采集、游戏编码、播放或设备切换哪一环。运行日志里的其他音频延迟警告与语音消息路径尚无因果证据。现场排查和后续分辨方法见[音频记录](audioCapturePeriodicArtifact20260924.md)。

当前游戏会话运行期间不改动其 Wine prefix 或应用安装物；需要新的录音、时间戳或游戏内复测时，等待玩家方便操作。

2026-09-24，`capture-resample-produced-frames.patch` 已从精确 CodeWeavers 26.1 源码构建为 x86_64 模块，并以本项目 Developer ID 签名；此前“缺少 x86 工具链”的判断已被本机已有 llvm-mingw + Bison 3.8.2 构建证据推翻。9 月 25 日风吟在 `test.2` 的国服语音消息录制与回听中确认低音量气泡音仍存在，语音连续；听感约位于 1–2、6–7、11–12 秒，因此该候选没有消除可感知症状，补丁与根因的关系仍未知。最新一条 12.67 秒 WAV 已在本机游戏数据中找到；离线数值未见削波，采样跳变本身不足以判定气泡音。应继续对同一文件做游戏内与独立播放器回听对照。复建、签名与边界见[音频补丁说明](../wineAudioPatch/README.md)和[音频记录](audioCapturePeriodicArtifact20260924.md)。
